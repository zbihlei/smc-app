# Rulebound — інструкції для Claude Code

Мова спілкування з власником (Michel): **українська**. Пояснюй простими словами, без зайвого жаргону.

## Що це
**Rulebound** (до 14.11.2026 — «SMC App») — локальний додаток на Mac: робоче місце трейдера, який торгує за записаними правилами. Скринер ситуацій за фільтрами, журнал угод з позначкою «за правилами / поза правилами», статистика й гіпотези, бектест, алерти на Mac і в Telegram. Комерційний фокус — **дисципліна**, а не сигнали. Стратегія Michel (Smart Money, ордерблоки 4h, v0.5.1) — лише перший набір фільтрів.

Цей додаток — **чорновик майбутнього веб-сервісу**: робимо базовий функціонал, вигляд і дизайн, які потім перенесемо у веб-версію (окремий репозиторій, пізніше).

Продуктові рішення, roadmap, Jira і комерційний аналіз ведуться окремо (чат-проєкт у claude.ai). Тут — лише розробка.

## Середовище
- Папка: `~/Rulebound` (до 14.11.2026 — `~/smc_app`). GitHub: `zbihlei/Rulebound` (**публічний** — нічого особистого й секретного в git).
- Python: системний CommandLineTools **3.9.6** (`/usr/bin/python3`). Код має бути сумісний з **Python 3.9** (без `match`, `X | Y` у типах тощо). Залежності: лише стандартна бібліотека + `requests`.
- Сервер додатка: **127.0.0.1:8765**, інтерфейс у браузері. Запуск — ярлик `~/Applications/Rulebound.app` (його збирає `make_app.py`).
- Час у логах (`results/*.csv`, `data/*.log`) — **місцевий час Mac (Київ)**, не UTC. UTC — лише у свічках Binance і кеші бектесту.

## Архітектура
| Модуль | Що робить |
|---|---|
| `app.py` | HTTP-сервер (~55 маршрутів `/api/*`), налаштування (`DEFAULTS`, `LIMITS`, `FLAGS`), запуск/зупинка скринерів, сповіщення Mac, `/api/restart` (`os.execv`), `fix_moved_paths` |
| `smc_screener.py` | скринер Binance USDT-M ф'ючерсів: структура 4h, зони, фільтри, R:R, бали, попередження; керується прапорцями CLI; `--selftest` |
| `screener_runner.py` | обгортка скринера: розклад сканів, `results/latest_app.json`, логи сигналів і «вибула» (`drop_reason`), зняття стопів 15m (`stop_sweep`) |
| `ltf.py` | уточнення на 15m, `LtfWatcher` (живі алерти) |
| `fx_runner.py`, `fx_source.py`, `mt5/SMC_Bridge.mq5` | форекс: свічки 28 пар із файлів MT5 (робот лише пише свічки, рівно один) |
| `spot_scan.py` | спот: «накопичення», «новий лістинг» |
| `journal.py`, `stats.py` | журнал угод (SQLite `data/journal.db`), бекапи, прив'язка сигналів; статистика в R, розрізи, гіпотези |
| `backtest_data.py`, `backtest_signals.py`, `backtest_trades.py` | бектест: кеш свічок, пошук сигналів, симуляція угод, розробка / поза вибіркою |
| `tg.py` | Telegram (алерти, профіль бота) |
| `gitsync.py` | автозбереження в GitHub (див. «Git») |
| `make_app.py` | збирає `Rulebound.app` (C-обгортка + `codesign -`) |

Фронтенд: ванільний JS без збирача — `static/app.js` (скринер, налаштування), `live.js`, `spot.js`, `journal.js`, `summary.js`, `strategy.js`, `history.js`, `backtest.js`, `index.html`, `style.css`; Lightweight Charts 4.2.0 у `static/vendor`. Скрипти класичні зі **спільною глобальною областю** — не дублюй імена функцій між файлами (тест це ловить). Сортування `S.rows` не змінює індекси DOM (`#c{idx}`) — шукай рядок за `idx`, не за позицією. Кольори в тестах перевіряй через обчислений стиль.

## Правила (обов'язкові)
1. **Секрети** (`SMC_TG_TOKEN`, `SMC_SHEET_URL`, `SMC_SHEET_TOKEN`) — лише змінні середовища в `~/.zshrc`. Ніколи не в код, git, settings.json, логи чи відповіді. Не просити надсилати токени. `apps_script/Code.gs` містить токен і виключений із git — не додавати.
2. **Жодної автоторгівлі й торгових агентів.** Додаток лише читає ринкові дані й надсилає сповіщення; робот MT5 лише пише свічки.
3. **Нова логіка скринера — за прапорцем, вимкненим за замовчуванням.** Вмикається лише після бектесту й рішення Michel.
4. **Перевірку «поза вибіркою»** (контрольні 4 міс. бектесту) відкриває лише Michel, якщо він прямо не попросив інакше.
5. **Письмову стратегію** (`data/strategy.md`) Claude сам не редагує. Фінансові теми — факти, не поради.
6. **Не видаляти** файли користувача (журнал, логи, бекапи) без явного прохання.
7. Перед зміною файлів у `data/` (вони поза git) — копія в `.claude_backups/<YYYYMMDD_HHMMSS>_<суть>/`.
8. Не перейменовувати внутрішні імена без потреби: `smc_screener.py`, змінні `SMC_*`, `BUNDLE_ID local.smcapp.launcher` (зміна скине дозволи macOS), `SMC_Bridge.mq5`. «SMC» там — назва стратегії (Smart Money Concepts), а не ключ Jira.

## Процедура зміни (Definition of Done)
1. Перед початком — `git status` чистий (інакше спитати Michel, що з незакоміченим).
2. Правка.
3. Регресія (усе має пройти):
   ```bash
   python3 smc_screener.py --selftest
   for t in tests/test_*.py; do python3 "$t" || echo "FAIL $t"; done
   node tests/test_code_gs.js
   ```
   UI-тести на Playwright (один раз на Mac: `pip3 install --user playwright && python3 -m playwright install chromium`). Тести піднімають власні сервери на інших портах — запущений додаток на 8765 не заважає. Новий функціонал — новий тест (`tests/test_vXYZ.py`, стиль `check(name, cond)`).
4. Версія: `APP_VERSION` в `app.py` (зараз **2.1.0**); скринер — версія в `smc_screener.py` (зараз **v2.11**).
5. **Запис в «Історію»** — у **обох** файлах: `static/changelog_seed.json` (у git) і `data/changelog.json` (на Mac; спершу бекап). Формат `{"entries":[...]}`, `json.dumps(..., ensure_ascii=False, indent=1)`; поля `id, date, approx, component (Скринер/Стратегія/Журнал/Додаток/Інструменти), version, title, what, why, result, trades`. Наступний id — **e073**. Разом оновити лічильники в `tests/test_history.py` (4 місця: N записів, N, N+1 після тестового додавання, N після видалення).
6. **Jira не заводимо.** Новий запис «Історії» — без ключа. Ключ «(RB-N)» у кінці заголовка дописується пізніше, після PM-ревʼю (проєкт Jira **RB**, до 14.11.2026 — SMC; номери ті самі).
7. Коміт і пуш (див. «Git»).
8. Сказати Michel, що перезапустити: скринер — «Стоп» → «Старт»; інтерфейс — ⌘R; `app.py`/`journal.py`/інші модулі сервера — кнопка «Перезапустити» в додатку; `make_app.py` — перезібрати ярлик, заново видати «Повний доступ до диска» і замінити ярлик у Dock.

## Git
- Комітити самостійно після кожної завершеної зміни (тести зелені), повідомлення українською: `v2.1.1: <що зроблено> (e073)`. Потім `git push`.
- У додатку є автозбереження (`gitsync.py`, налаштування `git_autopush`), яке саме комітить «Автозбереження vX: …» раз на хвилину. Під час роботи Claude Code воно має бути **вимкнене** («Налаштування» → GitHub), інакше закомітить недороблені правки. Якщо бачиш нові коміти «Автозбереження» поверх своєї роботи — скажи Michel.
- Великі зміни — в окремій гілці, злиття в `main` після перевірки Michel.

## Ключові налаштування і прапорці
Налаштування за замовчуванням: `approach 4` (%), `approach_atr 3`, `top 100`, `min_volume 30` (млн $), `entry_tol 25`, `min_stop_atr 0.6`, `trend strict`, `stop_wick`, `breakers`, `ltf_enabled`, `tg_enabled`, `spot_auto`, `sound`, `popup`, `fx_enabled False`.

Прапорці скринера: `--interval 4h --limit 500 --swing 3 --max-age 120 --max-zone 6 --min-rr 3 --fib-lo 0.5 --fib-hi 0.79 --ob-zone body|candle --no-breakers --entry-tol N --approach-atr N --btc-warn 1.5 --range-struct X --eq-levels X --selftest`. `--range-struct`, `--eq-levels` вимкнені (бектест: переваги немає).
