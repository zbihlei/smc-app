# SMC App — версія 0.4 (усі 4 етапи: «Скринер», «Журнал», «Підсумок», «Стратегія», запуск без Терміналу)

Локальний додаток у браузері (http://127.0.0.1:8765): кнопки Старт/Стоп скринера, таблиця кандидатів
з червоними рядками «ЦІНА В ЗОНІ», інтерактивні графіки кожного кандидата, лог скринера, налаштування.
Вкладка «Журнал»: усі угоди, додавання зі сигналу скринера або вручну, автоперевірка за правилами стратегії,
резервні копії. Журнал зберігається в додатку; запис у Google Таблицю — за бажанням (за замовчуванням вимкнено). Вкладка «Підсумок»: статистика як на аркуші «Підсумок» Google Таблиці плюс розрізи й перевірка гіпотез.

Кандидати для ручної перевірки, а не сигнали. Не фінансова порада.

## Що всередині
| Файл | Що робить |
|---|---|
| `app.py` | сервер на localhost (лише стандартна бібліотека Python) |
| `make_app.py` | створює «SMC App.app» для запуску без Терміналу (етап 4) |
| `static/strategy_seed.md` | стратегія v0.5.1 з Google Doc — початковий текст вкладки «Стратегія» |
| `stats.py` | підсумок і гіпотези (ті самі формули, що й аркуш «Підсумок») |
| `journal.py` | журнал: база SQLite, сигнали з `signals_log.csv`, перевірки, запис у Google Таблицю, резервні копії |
| `apps_script/Code.gs` | нова версія скрипта-приймача в Google (див. «Оновлення Code.gs») |
| `screener_runner.py` | запускає ТВІЙ `smc_screener.py` без змін і після кожного скану пише `results/latest_app.json` з даними графіків |
| `static/` | інтерфейс; бібліотека графіків лежить локально в `static/vendor` (не з інтернету) |

| `data/` | з'явиться після першого запуску: налаштування, лог скринера, стан процесу, **база журналу `journal.db`** і `backup/` |

## Встановлення (один раз)
1. Розпакуй архів, напр. у `~/smc_app`.
2. Поклади поруч свій `smc_screener.py` (v2.5): `cp ~/шлях/до/smc_screener.py ~/smc_app/`
   (або залиш його де є і вкажи шлях у вкладці «Налаштування»).
3. `requests` у тебе вже стоїть; якщо ні: `pip3 install requests`.
4. URL і токен Google Таблиці — у змінні середовища, щоб скринер, запущений із додатка, оновлював аркуш «Скринер».
   Відкрий `~/.zshrc` (`open -e ~/.zshrc`) і додай у кінець два рядки зі своїми значеннями:
   ```
   export SMC_SHEET_URL="https://script.google.com/macros/s/…/exec"
   export SMC_SHEET_TOKEN="твій_секрет_із_Code.gs"
   ```
   Збережи й відкрий новий Термінал. У вкладці «Налаштування» має з'явитися ✓ біля «Google Таблиця».
   Додаток ці значення ніде не зберігає й не показує.

## Запуск без Терміналу (етап 4) — рекомендовано
Один раз, у Терміналі, у папці додатка:
```
cd ~/Desktop/smc_app && python3 make_app.py
```
З'явиться **«SMC App»** у `~/Applications` (Finder відкриється на ньому): тепер він є в Launchpad і Spotlight (⌘+пробіл → «SMC App»).
Щоб був у Dock — перетягни його з Finder у Dock.
- Клік по «SMC App» запускає сервер додатка у фоні (якщо ще не запущений) і відкриває **окреме вікно Chrome без вкладок
  і адресного рядка**. Без Chrome — відкриє в браузері за замовчуванням.
- Змінні `SMC_SHEET_URL` / `SMC_SHEET_TOKEN` береться з `~/.zshrc`, як у Терміналі.
- Закрити додаток: **Налаштування → Закрити додаток**. Скринер, якщо працює, не зупиняється.
- Лог сервера: `data/app.log`; лог ярлика: `data/launcher.log`.
- Якщо перенесеш папку додатка — запусти `python3 make_app.py` ще раз. Прибрати ярлик: `python3 make_app.py --remove`.
- Кнопка «Відкрити в TradingView» у попапі скринера натискає клавіші в TradingView. Якщо скринер запущено з «SMC App»,
  macOS може попросити дозвіл для **SMC App** (Системні налаштування → Конфіденційність і безпека → Універсальний доступ).

## Запуск з Терміналу (як раніше)
- Термінал: `cd ~/smc_app && python3 app.py` — браузер відкриється сам.
- Або подвійний клік по `Запустити SMC App.command`. Перший раз macOS може не дозволити:
  правий клік → «Відкрити» → «Відкрити».

Далі все кнопками: «Старт» запускає скринер (з `caffeinate -i`, як твоя команда), «Стоп» зупиняє його так само, як Ctrl+C.
Стандартні параметри = твоя поточна команда: `--watch 30 --approach 4 --top 100 --popup --voice --tv-button --stop-wick`,
`--price-check 15`, `--min-stop-atr 0.6`, `--trend strict`, результати в `~/Desktop/results`. Змінюються у «Налаштуваннях»
(там же видно точну команду запуску). Нові параметри діють після перезапуску скринера (Стоп → Старт).

Алерти (попап, голос, звуки, «НОВА ПАРА», «ЦІНА В ЗОНІ» кожні 15 с) робить сам скринер — так само, як раніше.
Сторінка оновлюється сама кожні 5 с; після живого алерту рядок стає червоним, у назві вкладки браузера з'являється 🔴.

### Поведінка, яку варто знати
- Якщо закрити Термінал із додатком, **скринер працює далі** у фоні (щоб не зникли алерти). Знову запусти додаток —
  він підхопить скринер, і його можна зупинити кнопкою «Стоп».
- Повний скан іде раз на 30 хв, тож перші результати з графіками з'являються через 1–2 хв після «Старт».
  До того показується твій старий `latest.json` (без графіків) з позначкою.
- Якщо скринер упав (наприклад, немає мережі), угорі буде червоне повідомлення, а лог унизу відкриється сам.
- Кнопка «Перевірити скринер (selftest)» у «Налаштуваннях» запускає `--selftest` (має бути 51 OK).
- Твої файли `seen.json` і `signals_log.csv` у `~/Desktop/results` не змінюються: додаток лише додає поруч `latest_app.json`.

## Журнал (етап 2)
- **Імпорт з таблиці** — підтягує всі угоди з аркуша «Журнал» у локальну базу. Нічого не видаляє; повторний імпорт
  оновлює угоди з тими самими номерами. Після імпорту показує, чи збігається «Накопичено» з таблицею.
- **+ Угода зі скринера** — список сигналів із `signals_log.csv` (за 1–30 днів; «відсіяні» — окремим прапорцем).
  Вибір сигналу підставляє монету, напрямок і рівні скринера; ти змінюєш їх на свої фактичні.
- **+ Вручну** — для угоди не зі скринера. Якщо в лозі є схожий сигнал (та сама монета, напрямок, вхід біля зони,
  дати поруч), додаток запропонує його прив'язати.
- **Автоперевірка** (поки вводиш): R:R ≥ 3, вхід від середини зони, стоп за зоною, стоп вужчий/ширший за скринерний,
  ціль ближче за скринерну, вузький стоп < 1,5%, попередження скринера («ніж», «тісний стоп»), дата проти появи сигналу,
  результат більший за ризик. «За правилами?» і «По скринеру?» заповнюються самі (позначка «авто»), доки ти їх не змінив.
- **Ризик 0,5R** — перемикач у формі; результат вводиш у R пропорційно (стоп = −0,5R), як домовлено.
- **Калькулятор результату й MFE** у формі: кнопки «ціль» / «стоп» / «БУ» або поле «ціна виходу» заповнюють результат у R
  (з урахуванням ризику 0,5R); поле «найкраща ціна після входу» (Short — найнижча, Long — найвища) рахує MFE
  (MFE — у відстанях до стопа, без множення на ризик, як у журналі раніше).
- Інструмент записується без USDT: «WLDUSDT» → «WLD», як у решті журналу.
- **Порожній «Результат»** = угода ще відкрита. Потім клікни по рядку, допиши результат і збережи — рядок у таблиці оновиться.
- **Де живе журнал**: у базі `data/journal.db`. Запис у Google Таблицю вимкнено за замовчуванням
  («Налаштування → Журнал»); «Імпорт з таблиці» працює й без нього.
- **Резервні копії** (блок унизу вкладки «Журнал»): актуальна копія після кожної зміни; щоденна — стан на початок дня,
  до першої зміни (30 днів); «Зробити копію зараз» — ручні, не видаляються; «відновити» з будь-якої копії —
  поточний стан перед цим теж зберігається («перед відновленням»), тож відновлення можна скасувати.
  **Друга папка** («Налаштування → Журнал», кнопка «Використати iCloud Drive»): усі копії дублюються туди,
  тож журнал не пропаде навіть разом із диском Mac.
- **Запис у Google Таблицю** (якщо ввімкнено): угода №n пишеться в рядок n+2 аркуша «Журнал»; формули R:R / Накопичено / Просадка / Серія
  скрипт не чіпає. Якщо Google недоступний, угода зберігається в додатку з позначкою «!», а кнопка «Дописати» повторить.
- **Видалити** можна лише останню угоду (щоб номери не розійшлися); рядок у таблиці очищається, формули лишаються.
- Кнопка «CSV» завантажує журнал одразу (відкривається в Numbers / Excel / Google Таблицях).
- Якщо ввімкнено запис у таблицю й додаєш угоду прямо в Google Таблиці, зроби в додатку «Імпорт з таблиці»,
  інакше номери розійдуться (додаток це помітить і не перезапише чужий рядок).

## Стратегія
Вкладка «Стратегія» — твій документ стратегії (спершу — Strategy_v0.5.1 з Google Doc; картинок графіків там немає, лише їх описи).
- Зміст збоку, клік — перехід до розділу. **Редагувати** → текст у форматі Markdown → **Зберегти** (або ⌘+S).
- Кожне збереження кладе попередню версію в **Історію версій** (`data/strategy_history/`): її можна переглянути й відновити.
- Файл: `data/strategy.md`; копія йде й у другу папку резервних копій (iCloud Drive), якщо її задано.

## Підсумок (етап 3)
- **Період**: усі угоди / 90 / 30 / 7 днів / цей місяць. Рахуються лише закриті угоди; відкриті показано окремо.
- **Картки**: угод (+ / − / 0), вінрейт і беззбитковий вінрейт при твоєму середньому R:R, сума, середній R (очікування),
  profit factor, середній виграш / збиток, максимальна просадка й найдовша серія збитків (і поточні значення).
- **Крива накопиченого R** по угодах (наведи на крапку — номер, монета, результат), сірим — просадка від піку.
- **Гіпотези**: 1h CHoCH, «за правилами», вузькі стопи (< 1,5%), R:R ≥ 3 (урок №20), вхід від 1h OB проти 4h OB,
  угоди за скринером, цілі далі за 4R, стоп вужчий за скринерний. Висновок («поки на користь» / «поки проти» /
  «різниці не видно» / «мало даних») з'являється, коли в кожній групі ≥ 3 угод. До 50–100 угод — орієнтири, не доказ.
- **Розрізи**: за правилами, CHoCH, тип зони, підтримка 4h, R:R плану, ширина стопа, ведення угоди, скринер, напрямок,
  інструмент — угод, вінрейт, середній R, сума; позначка «мало» = менше 5 угод.
- **MFE**: скільки угод дійшли до 3R / 4R, скільки з них закрито в 0 або мінус, і сценарії «що було б» з фіксованою
  ціллю 3R / 4R або БУ на 3R (наближення: якщо ціна не дійшла до X, береться фактичний результат).
- **Відхилення від скринера**: для угод із прив'язаним сигналом — стоп вужчий за скринерний, вхід не від середини зони.
- У формі угоди «Ведення угоди» тепер має й варіанти стратегії «BE на 3R» та «BE на 3R + частина на 4R».
- Цифри звірено з аркушем «Підсумок» на 20 угодах (38 показників, `tests/test_stats.py`).

## Оновлення Code.gs (версія 3) — лише якщо вмикаєш запис у таблицю
v3 (0.2.1): дата угоди ставиться на полудень — у v2 через різницю часових поясів скрипта й таблиці дата могла записатися на день раніше.
Додаток показує підказку, якщо в Google ще стара версія.
Скрипт-приймач, що оновлює аркуш «Скринер», — окремий проєкт на https://script.google.com/home (не «Розширення → Apps Script»).
1. Відкрий цей проєкт, файл із `doPost`. Виділи весь код (⌘A) і заміни вмістом `apps_script/Code.gs` з цієї папки. Збережи (⌘S).
   Токен і id таблиці в новому файлі ті самі, що були.
2. **Розгорнути → Керувати розгортаннями** → олівець біля активного розгортання → «Версія: Нова версія» → **Розгорнути**.
   Адреса `/exec` не зміниться, нічого на Mac міняти не треба. Аркуш «Скринер» оновлюється як раніше.
3. Перевірка: відкрий адресу `/exec` у браузері — має бути `"version":3`. У додатку на вкладці «Журнал» з'явиться
   «Google Таблиця підключена (Code.gs v3)».
Стара версія скрипта будь-який запит сприймала як оновлення «Скринера», тому додаток спершу перевіряє версію
і без v2 у таблицю нічого не надсилає.
